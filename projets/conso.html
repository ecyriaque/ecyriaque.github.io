J'ai développé Conso pour un technicien qui devait suivre les consommations d'un site industriel et n'avait pas d'outil pour le faire. L'application rassemble les relevés de gaz, d'eau et d'électricité, les compare à des objectifs et permet de les exporter en CSV, Excel ou PDF. Chaque widget du tableau de bord peut être déplacé, affiché ou masqué selon les indicateurs à suivre.

D'où viennent les données

Les capteurs LoRa posés sur les équipements remontent un nombre d'impulsions et une température. L'API ENEDIS fournit les données des points de livraison électriques. Conso convertit les impulsions brutes en consommations réelles. Si un capteur décroche, le calcul peut être relancé sur la période concernée.

Les identifiants matériels des capteurs sont volontairement floutés sur cette capture.

Mise en production

Le code NestJS et React est regroupé dans un monorepo, avec PostgreSQL pour les données. Nginx sert l'application et Docker Compose gère les services. Cloudflare Access vérifie l'identité avant tout accès, y compris le mien, selon le modèle Zero Trust. L'intégration continue tourne sur GitHub Actions, avec des pipelines de build et de déploiement séparés.

Côté exploitation, les logs partent chez Datadog, l'API est protégée par Helmet et un rate limiter, un mode lecture seule permet de geler les écritures, et un scan de secrets tourne en pre-commit pour éviter qu'une clé finisse dans l'historique git.

Outils utilisés

NestJS, React, Vite, PostgreSQL, Docker Compose, Nginx, Cloudflare Access, GitHub Actions, Datadog, capteurs LoRa, API ENEDIS.
